# 截击舰锁定与跑路

:::tip 截击 ≠ 拦截
**截击舰**（Interceptor，如短剑级）靠速度与锁定距离抓人；**拦截舰**（Interdictor，如剑齿虎级）放拦截泡封路。两者定位完全不同，别混着叫。
:::

哈罗大家好是我，Nimos, 你们或许记得我上次发的关于如果观测隐形船进入隐形时间的帖子。

这次的帖子依然是关于一些没人知道的但是非常简单的游戏机制。不过首先，我不住在伦敦甚至不住在英国。我身在德国而且我的ping在宁静服务器一般在13ms到16ms。

我将会演示我在短短几周的顿们时间内是如何锁定并击杀几百艘跑路截击的。我会讲述我所有的思路以及游戏原理，但是如果你不give a fuck你可以跳到最后一章。

早在12月我跟我的朋友在Aridia的交通星系堵门。这里会经过很多想去艾玛采购的goons。当然，大部分人们用的都是跑路装截击，我们堵了几个小时只看见了无数在我们面前跳来跳去的截击们。

长达几年我一直觉得锁定跑路截击这件事像一个神话一样不现实。我自己从来没有在起跳小于2秒的情况下被抓过，所以我也想当然的去认为只要是起跳小于2秒的船出现在kb上就肯定是人为因素，比如网络不好啦等等。直到1-2年前我在静寂谷堵门，就能锁定任何在起跳小于2秒的船。

那么问题来了，为什么我有时候能锁定住这种“秒跳截击”但是有时候就不能呢？

The "Update-Order"

服务器更新顺序

我相信任何不只1个账号的玩家都看到过这种现象。就是当你开多个号的时候能发现他们的游戏界面并不是百分百同步。会有一些很轻微的延迟。

举个栗子：https://i.imgur.com/ymS8CA9.mp4

两个账号同一台电脑，当我从我的灵感里放出无人机时，无人机会在我的夜魔侠号的总览上提前620ms（毫秒）出现。

我记得我在静寂谷堵门的时候这种现象经常出现，我的主号明显比小号要快，也就是能够先看见船。

所以，为什么一个客户端会比另一个客户端刷新的更快呢？难道这跟你的角色名字有关？不是的，有时候我主号比小号快有时候小号比主号快。难道这跟船名有关？也不是，我经常在我的账号之间交易船，但是并不影响结果。

因此，我找到了4个会影响服务器刷新的因素：

- 进站/出站

- 过门

- 大量船进入、离开grid

- 随机，我也不知道为什么有时候就这样

起初我以为可能会有某种队列，每个客户端都按顺序去刷新。 我的理论是，当你通过进站或出站进入系统时，你会被排列在该队列中的随机位置。 而我想到的＃3理论依据是，当其他人被分配到队列中的位置时，他们可能会被放在你前面（插队），因此你会失去早期的位置。

但是，这个理论也有瑕疵。最明显的不成立的地方是客户端也客户端之间的延迟实在是太他妈的高。我所经历过最高的延迟有900ms ，在我的小号和主号之间。即使服务器以某种方式在客户端刷新之间进行了其他的运算（这本身是很难实现的），900ms仍意味着该服务器处于都要开始Tidi的边缘。有趣的是在另一端（另一个账号）却什么都没发生。同时，这也无法解释我会被没有理由的“插队”。

最终，我注意到＃3和＃4只会让我“时间倒流”，每当他们发生时，我的客户端都会发生一件被人们称为“橡皮筋”（rubberbanding）的现象。 具体表现为当屏幕上发生某件事时，然后一切都向后移动一瞬间，然后再次发生同样的事情。

这个观测结果使得我得出了以下可靠的理论：

当你通过出站或者过门进入一个星系而申请服务器刷新时，服务器会把你放置在一个独立于“服务器秒数”的一秒区间内。（注：在这里服务器秒数的原文是tick，大概意思是服务器的刷新频率，一个tick服务器就会刷新一下）从同时观察两个EVE的账户可以侧面证明这一点，它们每秒精确地更新一次，但以不同的毫秒为单位。

根据服务器秒中客户请求其第一次刷新的时间，你会或早或晚的得到新的刷新信息。 这意味着在服务器计算它的一秒与你的客户端实际接收到有关发生的最新信息之间可能会有长达一秒钟的延迟。

**当你看到“橡皮筋”现象时，你的刷新很可能是在服务器完成计算下一“秒”之前进行的。**

现在，要了解这一点，你必须知道服务器仅在实际更改网格（grid）时才发送刷新请求。 而且，我的意思不是仅仅指舰船的位置。 例如，如果一艘船在直线上对齐的另一艘船上运行，而它们都不改变速度，您的客户将自己计算自己的继续位置，并且服务器将不会发送刷新请求，直到一个他们实际上改变了他们的状态。 （我也通过在测试服上用一大堆角色去看网络交通来证实了这一点）。

没有收到新的刷新对于客户端并不是一个异常现象。对于你的客户端而言，这仅仅意味着“在听到下一条语音提示前，请沿当前道路行驶”这种感觉。

**那么，如果在服务器秒之前计划了客户端的更新，会发生什么？**

客户端正在等待你刷新的数据。 它在一秒钟内没有在预期的时间获得任何刷新西宁西，所以，它认为没有任何改变，并将继续显示未变动的网格（grid）。 然后，在几毫秒内，服务器延迟发送他的刷新信息，这个刷新信息才是“真实实际发生的事情”。 因此，客户端将所有内容重置为刷新的状态。这个状态就是一瞬间前服务器的状态。因此看起来一切都跳回并再次为玩家播放一边一瞬间前的画面。

现在，该理论与服务器宇宙内的刻度位置有何关系？ 其实，在“橡皮筋”现象刷新期间的较晚更新会重置你的刷新间隔，因此所有后续更新将在该间隔之后的1秒间隔内进行。 这意味着你现在比以前晚了1服务器秒。

这也能解释第三和第四因素，他们都是由于服务器的加载把你放在了一秒前。

Lock, Point and Warp Interactions

**锁定，反跳和跃迁交互**

这时候你可能在想：“你**怎么一直再讲服务器，你难道不应该讲秒锁吗？” 没错，所以我在文章开篇就说如果你不想看原理可以直接跳过，而且我依然会继续讲剩下的一小部分原理，所以如果你还是不想看那就继续跳过吧。

在这一章我会介绍一些跃迁的机制，而且在本篇中每次我提到跃迁，都默认为大于1秒但是小于2秒的起跳时间。

基本的跃迁顺序在不考虑任何外界因素的情况下应该是如下所示：

- 玩家点击起跳

- 服务器接受起跳指令

- 在下一个服务器秒内，服务器开始朝向你的舰船，从0速开始。我们把这一秒叫做第0秒。

- 在下一个服务器秒内，船应该依然在朝向中。我们把这一秒叫做第一秒。

- 在下一个服务器秒内，船只将满足起跳条件，然后进入跃迁状态。我们把这一秒叫做第二秒。

好了，现在有两件事大多数人知道，但是有些人依然有疑惑和误解：

- 不管你的船在秒与秒之间，你都不可能在这之间进入跃迁状态。换句话说，你如果很快可以在第一秒跃迁，或者慢一些会在第二秒跃迁。你不可能在第1.5秒进入跃迁。所以不管你的阿瑞斯的起跳时间是1.4秒还是1.99秒，你都应该是2秒的起跳时间。我也在测试服测试过，1.1秒和1.99秒的面板起跳时间对于真正的起跳时间毫无影响。

- 你的延迟与起跳速度无关。不管你是不是高ping战士，你的客户端唯一一个任务就是向服务器送出跃迁指令。然后服务器把跃迁指令排到队列中去，剩下的事情都是服务器自己的活，跟你的客户端延迟毫无关系了。

那么，如果有坏蛋的想锁你，这些步骤会怎样改变？

我们假设小明过门，发现了小红在堵门：

- 小明点击起跳

- 服务器接受小明的起跳指令

- 第0秒，服务器开始使小明的船朝向。

- 依然是第0秒，服务器刷新，小红看见了小明的船破隐形开始朝向。

- 还是第0秒。小红点击锁定小明的阿瑞斯。

在这时候，上文所讲的服务器的排列顺序就有关系了：

你们应该记得第三步第四步现象之间的时间可能在（据保守估计）50毫秒到1000毫秒之间。一个非常大的范围。

顺便提一句，锁定是可以在秒与秒之间开始的，但是完成锁定必须在正秒结束。

我们假设小红在他的刷新上延迟了，在500ms后才收到刷新，并且他有16ms的ping，同时他在以一秒50次的手速疯狂点击总览上的船。

最后，在上最大数量的感应增长的前提下锁定一个截击需要600ms，T0,T1,T2分别代表之前提到的第0,1和2秒。

- T0+0ms，服务器开始使小明的船朝向。

- T0+500ms，小红发现了小明的船破隐形并且开始朝向。

- T0+520ms，小红点击锁定小明的阿瑞斯，同一时刻客户端给服务器发送锁定指令。

- T0+528ms，服务器接受指令，然后计算出他需要600ms才能锁定阿瑞斯，于是把他规划在600ms后发出锁定完毕指令。

- T1+0ms，第0秒过，开始第一秒，但是在这一时刻其实什么都没发生。

- T1+128ms，这是服务器规划的完成锁定的时间

- T2+0ms，第1秒过，开始第二秒。小红锁定完毕。小明进入跃迁状态。

这种情况就是锁定与跃迁在同一秒发生。当这种情况发生时，小红会显示锁定成功，但是当他想反跳小明的时候会显示“该单位是无敌的“（target is invulnerable）。

但是，如果小红提前得到了刷新信息，仅仅有200ms的延迟，那一切都不一样了：

- T0+0ms，服务器开始使小明的船朝向。

- T0+200ms，小红发现了小明的船破隐形并且开始朝向。

- T0+220ms，小红点击锁定小明的阿瑞斯，同一时刻客户端给服务器发送锁定指令。

- T0+228ms，服务器接受指令，然后计算出他需要600ms才能锁定阿瑞斯，于是把他规划在600ms后发出锁定完毕指令。

- T0+828ms，这是服务器规划的完成锁定的时间

- T1+0ms，第0秒过，开始第一秒。小红锁定完毕。

- T1+200ms，小红点击反跳，同一时刻客户端给服务器发送反跳指令。

- T2+0ms，第1秒过，开始第二秒。小红的反跳开启，小明无法跃迁。

这里要注意的重要一点是，我们还有更多的空间可以容纳更多的延迟，但是并没有无限的余地。 你无需住在伦敦，但在欧洲确实会有所帮助。

The Guide / TLDR

秒锁教程

所以我到底是如何用这些信息换来我夜魔侠100多个截击击杀的？

首先，你需要4个感应投射。任何4中槽的船都ok。你的目的是感应强度到达3500ms。

然后的目标是尽早进行刷新，以便能够完成对第1秒的锁定。有3件事可以改变你的更新时间。

我个人用的方法其实并不聪明。我的技巧是，我反复进出我的星系，直到我有一个足够快的刷新时间。

**操作方法：**

跳入星系，激活感应增强。 过门一个起跳时间小于2秒的小号。 在小号上激活自动驾驶仪到另一个星门，快速切换到你的主号然后以你们单身多年的手速给我疯狂点击锁定你的那个号。 如果我成功锁定并反跳了我的小号，那证明了我的刷新时间已经被设置为足够锁定并反跳进入星系的任何其他起跳时间小于2秒船，直到服务器负载将我推回原位。 如果我没有锁定成功，而是收到“目标无敌”消息，那我会跳出，去隔壁星系，然后再回来。依次反复直到成功。

以上就是方法。
